### Carry-forward knowledge

1. **Apollo normalizes LAZILY — do not gate on `cache.policies.typePolicies`.** The runtime map starts EMPTY and fills per-type as reads/writes touch each type (observed: pre-write = `[]`, post-write = `[Query, HealthCheck]`, and normalization ERASES the literal `keyFields:false` from the entry). The user-supplied map lives at `cache.config.typePolicies` (visible via Reflect.walk; `config` is `protected` in typings). Any future policy test must assert against the CONFIG map, not the Policies runtime map.
2. Reading across that protected boundary without triggering `sonarjs/no-unsafe-type-assertion`: guarded `Reflect.get` descent with requireRecord-style throws — pattern documented in the suite header; reuse it rather than casting.
3. Importing `gql` from `@apollo/client` under Bun detonates `graphql-tag`'s UMD bundle (same known breakage as auth.test.ts, C2-phase3b) — parse documents via `import { parse } from "graphql"` in unit-tier suites instead. Note: ad-hoc `bun run <script>` execution of ANY `@apollo/client` root import is additionally flaky under Bun's loader (alternating crash across identical runs); the mandated runner's `bun test` pipeline is stable (error-link.map.test.ts + this suite both green repeatedly).
4. First-consumer checklist when BLT-03 executes: create document → `bun run generate:gqlSchema && bun run codegen` (graphql.ts gains `HealthCheckQuery`) → deep-or-barrel export per sharedDocuments AGENTS → Layout doc note → THIS cache entry already covers D4 (no apolloCache change needed).
