## Seven-step wiring as landed (REQ-010 order)

1. **`guardTransport(request)` FIRST** — lib-composed result union (`@/backend/lib/gateway` barrel). Any `ok:false` returns immediately through `transportRejectionResponse(kind, request)`; engine never invoked, context never constructed (spy-proven, TE suite).
2. **requestId** — on the failure branch resolved via `resolveRequestId(request.headers)` inside the rejection builder; on the success branch inside `createGraphQLContext`. SAME pure helper both branches ⇒ one correlation mint per request (the factory is the documented SINGLE resolution point — AGENTS.md :135; a second route-side resolution would fabricate a divergent UUID when the inbound header is absent).
3. **idempotencyKey** — realized IN the context factory (`ctx.idempotencyKey`; capture lives at exactly ONE site per D10/REQ-004 — route-side duplication prohibited by 3.3's own SR gate; propagation-only contract documented on `GatewayRequestMetadata`).
4. **`ctx = await createGraphQLContext(request)`** via the Apollo handler context hook (extended in place by Task 3.3).
5–6. **Engine ordering UNCHANGED** — validate → scopeAuth/authScopes → resolver all run INSIDE Apollo execution (`startServerAndCreateNextHandler`); rate-limit tier stays AFTER transport guards and BEFORE the engine (F8 machinery preserved verbatim incl. fail-open behavior, 429 block, headers).
7a. `finalizeGraphqlErrors` runs at Apollo `willSendResponse` BEFORE the handler future resolves (DEV3-002 registration site untouched: finalizer plugin + single `attachRawErrorHop` hop + `hideSchemaDetailsFromClientErrors`/`includeStacktraceInErrorResponses` posture preserved; `introspection: !isProduction` live form kept verbatim — wording/test-lock owned by 3.4; `allowBatchedHttpRequests: true` preserved for BatchHttpLink).
7b. **Unconditional cookie merge** — `flushAuthCookies(response, engineRequest)` appends EVERY `ctx.authCookieOut` entry via `headers.append("Set-Cookie", …)` (NEVER `.set`) after finalize, on success AND error paths (REQ-042). The merge was MOVED out of `withRateLimit` to step 7b; the pre-existing request-scoped `WeakMap<NextRequest, Context>` hand-off channel is retained (GC-safe, F8 item).
7c. JSON response returned; domain errors ride HTTP 200 (Apollo convention).
