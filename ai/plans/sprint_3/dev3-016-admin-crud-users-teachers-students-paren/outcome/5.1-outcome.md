## Zero-leak gates

- **`id`-first normalization:** Every successful payload's first key is `id` (Apollo cache normalization rule from `frontend/graphql/sharedDocuments/AGENTS.md`).
- **No `passwordHash` exposure:** A deep key-walk (`deepFindKey`) recursively traverses every successful response payload (objects + arrays, never strings) and asserts that no key with the name `passwordHash` exists at any depth.
- **JR-C-1 (denial-no-audit rule):** Every Tier 1 + Tier 2 + Tier 4 denial case captures `countAllAuditRows()` BEFORE and AFTER the operation and asserts `auditAfter === auditBefore` (zero new audit rows emitted for denials).

## Carry-forward notes

- The `ADMIN_ROLE_CREATION_FORBIDDEN` runtime role-pre-guard is covered at the
  SERVICE tier by Journey C step 3 (admin user-management service-layer test
  in `test/workflows/admin/admin-user-denials.journey.test.ts`). At the GraphQL
  tier, the `RegisterPublicRole` SDL enum structurally excludes `Admin` — so a
  raw `role: Admin` literal in the document is rejected at schema validation
  (`GRAPHQL_VALIDATION_FAILED`) before the resolver runs. This is the FIRST
  line of BFLA defense; the runtime role-pre-guard is the SECOND line, only
  reachable through transport-tamper that bypasses the SDL validator (e.g., a
  custom-serialized HTTP body that lies about the type). The integration suite
  proves the SDL gate holds; the journey proves the runtime gate holds.
- Tier 3's "second soft-delete" assertion uses `USER_ALREADY_DELETED` (the
  domain-typed wire code), NOT `ADMIN_USERS_ALREADY_DELETED`. The
  `ADMIN_USERS_*` prefix is the locale-namespace grouping for copy, NOT the
  wire-code prefix. The wire codes are flat (`USER_ALREADY_DELETED`,
  `USER_NOT_DELETED`, `USER_NOT_FOUND`, `USER_SELF_DEACTIVATION_FORBIDDEN`,
  `ADMIN_ROLE_CREATION_FORBIDDEN`).
