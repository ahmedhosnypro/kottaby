## What Was Implemented

### (A) `escapeLikeWildcards` utility — D6 RESOLVED ✅

**File:** `backend/lib/db/escape-like-wildcards.ts`

**Signature:**
```ts
export function escapeLikeWildcards(input: string): string
```

**Behavior:** Escapes `\`, `%`, `_` (in that order — backslash FIRST so the subsequent `%`/`_` escapes are not themselves treated as escapes by PostgreSQL) by prefixing each with `\` (the default ILIKE escape char). This is the canonical substrate for ALL future admin search surfaces; never fork a second sanitizer (REQ-034 binding).

**Layer contract:** The directory SERVICE escapes + composes the `%…%` wrapper BEFORE passing to the repository. The repository receives the final escaped + `%…%`-wrapped pattern string and binds it directly to `ilike(column, pattern)` without re-escaping. This is documented in the file docstring.

**Method signatures (ALL `tx?: DBTransaction` optional-last; reads via `queryDb(tx)` convention):**

```ts
export namespace AdminUserRepository {
  export async function listDirectory(
    filters: NormalizedAdminUserFilters,
    limit: number,
    offset: number,
    tx?: DBTransaction
  ): Promise<AdminUserDirectoryRow[]>

  export async function countDirectory(
    filters: NormalizedAdminUserFilters,
    tx?: DBTransaction
  ): Promise<number>

  export async function findDetailById(
    id: number,
    tx?: DBTransaction
  ): Promise<AdminUserDetailRow | null>

  export async function updateProfileFields(
    id: number,
    patch: AdminUserUpdateDbPatch,
    tx?: DBTransaction
  ): Promise<AdminUserSafeSelect | null>

  export async function setDeletedOnce(
    id: number,
    target: boolean,
    tx?: DBTransaction
  ): Promise<AdminUserSafeSelect | null>

  export async function existsById(
    id: number,
    tx?: DBTransaction
  ): Promise<boolean>
}
```

**Key design decisions:**
- **listDirectory** — single query: `users LEFT JOIN applicants/teacher/students` (shared-PK) + scalar subselects (`parentLinkedChildrenCount` count-subquery on `students.parent_id`; `studentHasActiveSubscription` EXISTS-subquery on `subscriptions` active-window); ANDed filter chain; `search` (already-escaped + `%…%`-wrapped by the service) via parameterized `ilike` over `fullName`/`email`; `ORDER BY created_at ASC, id ASC`; `LIMIT/OFFSET`.
- **countDirectory** — same WHERE, no joins.
- **findDetailById** — detail projection single-row (LEFT JOIN all role children).
- **updateProfileFields** — whitelisted `AdminUserUpdateDbPatch` + server `updatedAt`, `RETURNING` (safe select — `passwordHash` structurally absent).
- **setDeletedOnce** — single guarded UPDATE with NULL-safe inverse-state guard (D4: `is_deleted = false OR is_deleted IS NULL` for delete; `= true` for reactivate) + `deleted_at`/`updated_at` + `RETURNING`. Single statement (no read-then-write per REQ-041).
- **existsById** — cold-path existence probe (used to disambiguate zero-row `RETURNING` into `USER_NOT_FOUND` vs typed CONFLICT).
- **Repository purity:** no business logic, no permission checks, no localized strings. No cross-layer imports.
- **No prepared statements** (filters are dynamic AND chains); **no inline `--` comments** inside any `sql` template; **all predicates Drizzle-parameterized**; **no raw string-concatenated SQL**.
