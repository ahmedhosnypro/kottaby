```ts
export const ANONYMOUS_ACTOR_ID = 0;  // sentinel for "anonymous" at the service layer

export interface JourneyFixtureSnapshot<T> { readonly row: T; }
export interface JourneyActor<TChild = unknown> {
  readonly user: UserSelectType;
  readonly child: TChild;
  readonly userSnapshot: JourneyFixtureSnapshot<UserSelectType>;
  readonly childSnapshot: JourneyFixtureSnapshot<TChild>;
}
export interface JourneyCast {
  readonly admin: JourneyActor<AdminSelectType>;
  readonly student: JourneyActor<StudentSelectType>;
  readonly parent: JourneyActor<ParentSelectType>;
  readonly applicant: JourneyActor<ApplicantSelectType>;
  readonly certifiedTeacher: JourneyActor<TeacherSelectType>;
}
export interface JourneyFixtureRegistry {
  readonly prefix: string;
  readonly userIds: number[];
  trackUserId(id: number): void;
}
export interface JourneyFixtureBundle {
  readonly cast: JourneyCast;
  readonly registry: JourneyFixtureRegistry;
}
export async function createJourneyFixtures(prefix: string): Promise<JourneyFixtureBundle>;

// test/workflows/helpers/journey-cleanup.ts
export async function journeyCleanup(registry: JourneyFixtureRegistry): Promise<void>;
```

## Scaffold Decision

The `test/workflows/AGENTS.md` rules file was committed in `e39096f` (Phase 0 baseline), but `test/workflows/helpers/` was MISSING in the tree. This task scaffolded the helper layer FIRST:

1. `journey-fixtures.ts` — per-domain actor-cast provisioner. Cast = 5 REAL users (super admin + student + parent + applicant + certified teacher) + their role-child rows. All created in a single committing `db.transaction(...)` so they persist across the journey's service calls. Each actor's row is byte-captured in a `JourneyFixtureSnapshot<T>` for immutability assertions. Every created user id is tracked in `JourneyFixtureRegistry.userIds` for `afterAll` cleanup.

2. `journey-cleanup.ts` — hard-delete teardown. Deletes tracked ids in FK-safe order: `audit_logs` (where `actor_id IN ids` — `ON DELETE RESTRICT` requires this first; defensive cleanup of `entity_id`-referencing rows via raw parameterized `WHERE entity_id = ANY($1::int[])` to sidestep Drizzle's `inArray` typing friction on nullable integer columns) → role-child rows (`teacher`/`applicants`/`students`/`parents`/`admin`) → `users`. Reverse-order traversal so journey-created rows delete before cast fixtures.

3. `index.ts` — pure `export *` barrel (one `/` max per export path per the AGENTS.md rule).

The helpers are designed for REUSE — Journey B/C (Task 2.2) provisions the same full cast (admin + student + parent + applicant + certified teacher) and uses the same `journeyCleanup` for teardown. Future journeys (e.g. session governance DEV3-021, financial auditing DEV3-022b) may extend the helpers with additional role-child provisioning functions; the existing cast members stay untouched.

4. **Service contract** (per plan §4.1, EXTENDED per the journey tests):
   ```ts
   listDirectory(
     filters: AdminUserFiltersSubmitInput, page: number, pageSize: number,
     locale: string, actorId: number, outerTx?: DBTransaction
   ): Promise<AdminUserPageReturnType>;
   getUserDetail(
     userId: number, locale: string, actorId: number, outerTx?: DBTransaction
   ): Promise<AdminUserDetailReturnType>;
   createUser(
     input: AdminCreateUserSubmitInput, actorId: number, locale: string, outerTx?: DBTransaction
   ): Promise<AdminUserDetailReturnType>;
   updateUser(
     id: number, patch: AdminUpdateUserPatchInput, actorId: number, locale: string, outerTx?: DBTransaction
   ): Promise<AdminUserDetailReturnType>;
   setUserDeleted(
     id: number, deleted: boolean, actorId: number, locale: string, outerTx?: DBTransaction
   ): Promise<AdminUserDetailReturnType>;
   ```
   - The journey tests pass `actorId` on EVERY service call (including reads) for defense-in-depth. The plan §4.1 contract omits `actorId` on reads — Task 2.4 must extend the contract to include it on every method.

5. **Defense-in-depth authorization at the service layer**:
   - `actorId = 0` (the `ANONYMOUS_ACTOR_ID` sentinel) → service fetches user 0, finds null, throws `UnauthorizedError` (translated `tErrors.unauthorized`).
   - `actorId` resolves to a real non-admin user → service throws `ForbiddenError` (translated `tErrors.forbidden`).
   - `actorId` resolves to an admin → proceed with the operation.

6. **ConflictError custom-code extension**: the journey asserts `error.code === "USER_SELF_DEACTIVATION_FORBIDDEN"` (step A7) and `error.code === "ADMIN_ROLE_CREATION_FORBIDDEN"` (step C3). The current `ConflictError` constructor hardcodes `code = "CONFLICT"`. Task 2.4 must extend `ConflictError` to accept a custom code (mirror `ValidationError`'s overloaded constructor: `new ConflictError(message)` OR `new ConflictError(code, message, options?)`).

7. **createUser return shape**: `AdminUserDetailReturnType` (not `RegistrationReturnType` — the journey asserts `result.id` / `result.role` / `result.isDeleted` / `result.deletedAt` / `result.fullName` directly).

8. **Audit row composition**: `actorId = cast.admin.user.id`, `actionType ∈ {Create, Update, Delete, Reactivate}`, `entityType = "user"`, `entityId = newStudent.id` (or `newApplicant.id`). The journey asserts exactly one such row per successful mutation via direct `audit_logs` table select (never spied).

9. **No-audit-on-denial rule**: denial paths (`setUserDeleted(ownId, true)`, non-admin actor calls, anonymous actor calls, `createUser(role=admin)` tamper) MUST emit ZERO audit rows. The journey asserts this via `countAllAuditRows()` before/after the denial (delta = 0).
