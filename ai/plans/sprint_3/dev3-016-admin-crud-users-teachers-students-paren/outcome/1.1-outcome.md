### Notable design reconciliations

- **`dateOfBirth?: string | null` vs. plan.md §2.2's `dateOfBirth?: Date`**: the task spec mandated `dateOfBirth?: string | null`. Verified against the actual `UserSelectType.dateOfBirth` inferred type — Drizzle's `date("date_of_birth")` column (no `mode: "date"`) yields `string | null` in `$inferSelect` (verified via a temp-type probe + `bun tsgo` error `Type 'Date' is not assignable to type 'string'`). This matches the established codebase precedent — no `DateTime` scalar exists anywhere in the Pothos builder (per `backend/graphql/pothos/teachers/applicant.pothos.ts:16-18` — timestamps are exposed as ISO-8601 strings via `t.exposeString(...)`). Choosing `string | null` keeps `AdminUpdateUserPatchInput` structurally compatible with `AdminUserUpdateDbPatch` (which inherits the same type via `Pick<UserSelectType, ...>`), so Task 2.4's field-by-field mapping produces no type friction.
- **All imports `import type`**: the file is pure types — no runtime expressions, no enum narrowing at this layer. Biome's `lint/style/useImportType` would auto-normalize value imports to type imports (per the existing precedent in `backend/types/teachers/applicant.types.ts`); explicit `import type` is the canonical form. Consumer services (Task 2.4) value-import `UserRole`, `Gender`, `AdminUserGovernanceFilter`, `AuditActionType` for their own runtime narrowing.

### Field-level carry-forward for Task 2.3 / 2.4

1. **`AdminUserListItemReturnType.role: UserRole`** — the service MUST re-apply the enum via `toUserRole(row.role)` (fail-closed on corrupt stored values) before assigning to this field. Never an `as UserRole` cast.
2. **Governance booleans null-coalescing** — the `users` schema columns `isDeleted`, `suspended`, `isBlocked` are `boolean | null` (no `notNull()` in `backend/db/schema/users/users.ts`). The service MUST null-coalesce (`row.isDeleted ?? false`) before assigning to `AdminUserListItemReturnType.isDeleted` (typed `boolean`).
3. **`applicantStatus: ApplicantProfileReturnType["status"] | null`** — service MUST `isApplicantStatus(row.applicantRow?.status)` (fail-closed) before assigning; corrupt stored statuses map to `null`, NOT to a thrown error.
4. **`AdminUserUpdateDbPatch` field set is identical to `AdminUserUpdatePatchInput` field set** — Task 2.4 builds the DB patch field-by-field (NEVER via spread) per REQ-016/REQ-031; the types are structurally compatible because `AdminUserUpdateDbPatch.dateOfBirth` is `(string | null) | undefined` and `AdminUpdateUserPatchInput.dateOfBirth` is `string | null | undefined` — assignable both ways.
5. **`AdminUserDetailReturnType extends AdminUserSafeSelect`** — Task 2.4 must populate ALL `AdminUserSafeSelect` fields (id, fullName, email, phone, role, dateOfBirth, gender, country, isDeleted, deletedAt, suspended, suspendedAt, suspendedPeriodDays, isBlocked, blockedAt, lastActiveAt, createdAt, updatedAt) PLUS the four role-child slots (applicant, teacher, student, parent). The role-child slots are independently nullable per row (only the matching slot is non-null).
6. **`AdminStudentSnapshotReturnType.balanceTrial` + `trialGrantedAt`** — D7 carry-forward: these slots will be `null` until DEV1-004 lands. Task 2.4's `getDetail` service returns `null` for these fields unconditionally (no conditional branch needed at this stage).
7. **`AdminUserListItemReturnType` uses nullable booleans** (`studentHasParentLink: boolean | null`, etc.) because the headline only computes when `role === 'student'`. Task 2.3 repo `listDirectory` SQL/projects: when `role !== 'student'`, return `null`; when `role === 'student'`, compute via subquery/exists.
8. **`AdminCreateUserSubmitInput.role: RegisterPublicRole`** — Task 3.1's Pothos input must declare `role: RegisterPublicRolePothosEnum` (NOT `UserRolePothosEnum`) — the public registration enum excludes `admin` at the type level. Task 2.4's service does not need to runtime-validate `role !== 'admin'` (the enum layer guarantees it); it only needs to runtime-validate that the `role` field is present (REQ-031 BOPLA discipline).
