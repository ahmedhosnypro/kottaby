## What Was Implemented

Per `specs.md` REQ-051 + `plan.md` §2.5 line 277, an `adminUsers` sub-block was added to the `errors` locale namespace. The structure is **nested** (a property on `ErrorsLabels` whose value is an inline interface with six leaf-string keys), matching the plan-mandated shape:

```ts
readonly adminUsers: {
  readonly userNotFound: string;
  readonly userAlreadyDeleted: string;
  readonly userNotDeleted: string;
  readonly userSelfDeactivationForbidden: string;
  readonly adminRoleCreationForbidden: string;
  readonly userPatchEmpty: string;
}
```

The six new leaf keys are admin-user-management-specific failure modes (lookup miss, conflict on already-deleted, conflict on not-deleted reactivate, self-deactivation guard, admin-role-creation denial, empty-patch validation deny). Each is a self-contained localized sentence — no key echo, no internal disclosure (no constraint names, no SQL, no stack hints, no email addresses, no user IDs, no role values).

Existing keys (`unauthorized`, `forbidden`, `validation`, `conflict`, `duplicateRequest`, `notFound`, `internalServerError`, `badRequest`, `serviceUnavailable`, `rateLimitExceeded`, `accountDeleted`/`accountBlocked`/`accountSuspended`, `tokenExpired`, `forbiddenRole`, `applicantNotFound`, `applicantCooldownActive`, `applicantStatusCorrupt`, `invalidLocale`, `invalidOrigin`, `failedToSetLocale`) are REUSED — no near-duplicate was introduced. The six new keys are admin-user-specific scenarios not semantically covered by any existing key (e.g., `userNotFound` differs from `notFound` because the admin surface uses entity-qualified `NotFoundError("USER", …)` whose localized copy is admin-surface-scoped, not the generic `notFound` used by the gateway's transport rejections; `userSelfDeactivationForbidden` and `adminRoleCreationForbidden` are operation-specific denials with no existing-key semantic equivalent).

## Carry-Forward Knowledge for Downstream Tasks

### Exact key paths for Task 2.4 (AdminUserManagementService)

The service layer consumes the new keys via property access on the localized bundle:

```ts
// Inside AdminUserManagementService methods (Task 2.4), via getServerTranslations:
import { getServerTranslations } from "@/shared/locale/server";

const { errorsTranslations: tErrors } = getServerTranslations(locale);
//                                                 ^^^^^^^^^^^^^^^^^^^^^^^^^^
// (or held-variable form: const t = getServerTranslations(locale, "errors").errorsTranslations)

// REQ-013 lookup miss:
throw new NotFoundError("USER", tErrors.adminUsers.userNotFound);

// REQ-017 soft-delete already-deleted conflict:
throw new ConflictError("USER_ALREADY_DELETED", tErrors.adminUsers.userAlreadyDeleted);

// REQ-018 reactivate non-deleted conflict:
throw new ConflictError("USER_NOT_DELETED", tErrors.adminUsers.userNotDeleted);

// REQ-019 self-deactivation guard (before any write):
throw new ConflictError("USER_SELF_DEACTIVATION_FORBIDDEN", tErrors.adminUsers.userSelfDeactivationForbidden);

// REQ-015 admin-role-creation denial:
throw new ValidationError("ADMIN_ROLE_CREATION_FORBIDDEN", tErrors.adminUsers.adminRoleCreationForbidden);

// REQ-016 empty-patch validation deny:
throw new ValidationError("USER_PATCH_EMPTY", tErrors.adminUsers.userPatchEmpty);
```

The property-access path `tErrors.adminUsers.<leafKey>` is the canonical consumer shape. NEVER use dynamic `t('adminUsers.userNotFound')` string-concatenated lookup — the compile-time `MessageSchema`/`ErrorsLabels` typing guards key-parity ONLY for property access.

### Downstream re-use — DO NOT duplicate

The six new keys cover admin-user-management-specific scenarios only. Task 2.4 service implementations SHALL reuse the existing keys for all other failure modes:

| Failure mode | Reuse existing key | DO NOT mint new |
|--------------|--------------------|----------------|
| Anonymous caller (401) | `errorsTranslations.unauthorized` | — |
| Authenticated non-admin caller (403) | `errorsTranslations.forbidden` | — |
| Malformed pagination/enum input (VALIDATION) | `errorsTranslations.validation` (+ `extensions.fields[]` for field-mappable failures per REQ-050) | — |
| Duplicate email (23505 → ConflictError) | `errorsTranslations.conflict` (or `duplicateRequest` if the consumer surfaces idempotent-replay UX) | — |

| Service unavailable | `errorsTranslations.serviceUnavailable` | — |
| Rate-limited | `errorsTranslations.rateLimitExceeded` | — |
