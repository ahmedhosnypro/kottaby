### NO-AGGREGATOR STATEMENT (explicit)

There is **NO aggregator job** (`ci-verdict` / `all-green` / `gate`) anywhere in this pipeline, and none may be introduced merely to simplify branch protection. Per plan REQ-046 this is the *preferred default*: each named check is individually required (REQ-018). The aggregator was evaluated and REJECTED because an aggregate either (a) fails-if-any-fails but then still needs every constituent marked individually required anyway to prevent merged-by-bypass gaps, or (b) collapses attribution so a red PR can no longer be traced to its single failing domain at a glance — the failure-attribution contract (REQ-026/053) that this ticket's step naming, job split, and sabotage evidence (Phase 5) are built on. Any future re-evaluation must cite REQ-046's rejected-alternate rationale and show why per-check requirement stopped working.

## 3. Exact apply command (REST, api-version aware)

**Payload file** — stage as e.g. `/tmp/dev3-ruleset-payload.json`:

```json
{
  "name": "develop-and-main-required-checks",
  "target": "branch",
  "enforcement": "active",
  "conditions": {
    "ref_name": {
      "include": ["refs/heads/develop", "refs/heads/main"],
      "exclude": []
    }
  },
  "bypass_actors": [],
  "rules": [
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": true,
        "required_status_checks": [
          { "context": "workflow-sanity",  "integration_id": 15368 },
          { "context": "quality",          "integration_id": 15368 },
          { "context": "dbml-validation",  "integration_id": 15368 },
          { "context": "docs-validation",  "integration_id": 15368 },
          { "context": "tests-db",         "integration_id": 15368 },
          { "context": "tests-services",   "integration_id": 15368 },
          { "context": "tests-ui",         "integration_id": 15368 }
        ]
      }
    }
  ]
}
```

(`integration_id: 15368` is the stable GitHub Actions app id used for status checks produced by workflows.)

**Creation command** — expects HTTP **201 Created**, echoes the new ruleset id:

```bash
gh api \
  --method POST \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  repos/ahmedhosnypro/kottaby_academy/rulesets \
  --input /tmp/dev3-ruleset-payload.json \
  --jq '{id: .id, name: .name, enforcement: .enforcement, html_url: .html_url}'
# equivalent REST call: POST /repos/{owner}/{repo}/rulesets
```

```bash

  --jq '{name, target, enforcement,

         bypass_actors,
```
