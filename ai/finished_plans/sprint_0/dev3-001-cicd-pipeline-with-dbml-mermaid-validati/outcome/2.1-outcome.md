### DEFINED BEHAVIOR decisions (all asserted in tests)

1. **Branch semantics (plan-literal resolution).** The executing brief floated "docs md without fence → false"; the plan's §4.2 CODE makes a watch-pattern hit return `true` immediately (docs markdown validates even without a fence; `.mmd` validates even with `content === null`). The PLAN was followed (it is the binding contract and Task 2.3 consumes this exact semantics); both independent true-gates are separately asserted, plus fallthrough-false cases.
2. **Fence detection = raw substring `contains("```mermaid")`**, deliberately NOT Markdown-aware: inline-code spans, four-backtick outer fences, and mid-line occurrences DO count (conservative over-inclusion — the downstream validator owns strict per-block parsing and can never be silently skipped for real diagrams). Escaped-backtick prose (`\`\`\`mermaid` written backslash-escaped) does NOT contain the raw sequence → no match. Case-sensitive; ```` ``` mermaid ```` / tilde fences do not match (documented precision limit — validator remains the source of truth).
3. **Deletion policy lives in the set-builder**: ANY candidate whose `readContent` resolves `null` is excluded unconditionally — including deleted `.mmd` files — because a nonexistent path would crash the spawned validator.
4. **Parsing**: split on `\r?\n`; per-line surrounding-whitespace trim (CI-log noise tolerance); interior spaces preserved verbatim; empty lines ignored; duplicates collapse.
5. **Sort**: explicit relational comparator (`compareUtf16`) — locale-independent UTF-16 code-unit ascending order (sonarjs demanded an explicit comparator; `localeCompare` was REJECTED because ICU collation varies between machines and CI must be deterministic).
6. **Security posture (Tier 4)**: traversal-shaped entries pass through VERBATIM as opaque strings — the pure core performs no filesystem resolution/rejection; sanitization belongs to the validator layer it feeds.
7. **Assumed diff format**: unquoted, forward-slashed, repo-root-relative lines exactly as `git diff --name-only` emits (no `a/ b/` prefixes); Windows-style separators therefore rank as generic `.md` candidates rescued only by the content fallback (asserted).
