## 1. What Was Built

**`scripts/ci/materialize-env-test.ts`** — `.env.test` materializer per plan §4.3 / Task 1.2 carry-forwards:

| Piece | Contract |
|---|---|
| `materializeEnvTest(options?)` | Reads template → parses → sentinel-substitution from env source → writes output. Throws named errors on the two contract failures; everything is DI-injectable (`templatePath`, `outputPath`, `env`). |
| `parseEnvTemplate(text)` | Split `\r\n`/`\n`/`\r`; ignore blank + `#` comment lines (indented too); split on FIRST `=` (values may contain `=`); trim both sides; malformed/keyless lines skipped deterministically; duplicate keys keep first position + LAST value; empty-string values preserved. |
| `EnvTemplateMissingError` | Message exactly `CI env template .env.test.ci missing` (basename of configured path). |
| `RequiredCiEnvMissingError` | Message exactly `missing required CI env variable: <KEY>` — fail-fast on FIRST offender in template order. |
| `runMaterializeEnvTestCli(io)` | Injectable CLI shell: success → stdout = key names (one per line) + counts summary line, exit 0; failure → stderr = error message verbatim, exit 1. |
| entrypoint | Thin `if (import.meta.main)` forwarding to the CLI shell — zero logic duplication. |

**Design decisions recorded:**
1. **Repo-root resolution**: `resolve(import.meta.dir, "..", "..")` — invocation is cwd-independent, matches `scripts/validate-dbml.ts` family conventions.
2. **DI-first**: paths/env are optional params with root defaults (plan §4.1 explicitly models `readContent`-style injection for this ticket's scripts); tests run against `mkdtemp` sandboxes and NEVER touch the live repo tree. The real entrypoint stays a 6-line shell.
3. **Failure style**: single-error-first (fail-fast) with exact-string messages, chosen over collect-and-report because tasks.md Tier 1 says "assert thrown message contains" ONE key name; wrapper prints the message to stderr then exits 1 — exactly plan §4.3 steps 1/3 wording.
4. **Override presence semantics**: `undefined` ⇒ missing; empty string ⇒ PRESENT (copied as `KEY=`). Boundary pinned by test (documented so workflow authors know an accidentally-empty secret fails LATER at DB connect, not here).
5. **Write mechanics**: `mkdir(outputDir, recursive)` → `open(path,"w",0o600)` → write → `chmod(0o600)` unconditionally (tightens pre-existing lax perms regardless of umask) → close. Re-runs are byte-idempotent overwrites (Tier 3 asserted incl. tampered-file recovery).
6. **REQ-038 stdout discipline**: only key NAMES + integer counts ever reach stdout/stderr; unit Tier 4 asserts both override VALUES and literal template VALUES are absent from captured buffers even on SUCCESS.
