Two environment-discovery results sharpened the final shape (both reproduced on demand):

1. **`generate:gqlSchema` hard-requires a non-empty `DATABASE_URL`.** `backend/db/index.ts:79` initializes `const db = drizzle({ client: getPool() })` at module scope ⇒ `requireEnv("DATABASE_URL")` throws BEFORE any connection attempt (captured stderr: `Required environment variable "DATABASE_URL" is not set…at getPool (backend/db/index.ts:54)`). No server needed — only the variable.
2. With that satisfied, the whole chain runs env-free otherwise (proved with `env -u DATABASE_URL -u TEST_SERVER … && git diff --exit-code` → `CHAIN_EXIT=0`, TREE_CLEAN).

Therefore the quality job supplies it through the COMMITTED INERT TEMPLATE instead of adding any `DATABASE_URL:` mapping outside tests-db (which would break tasks.md 3.3.SEC "no job other than tests-db defines DATABASE_URL" and the brief's grep). Final proof of the EXACT shipped chain in an empty-env shell simulating CI:

```
$ env -u DATABASE_URL -u TEST_SERVER bun --env-file=.env.test.ci run generate:gqlSchema && bun codegen && git diff --exit-code
```

The value injected is `.env.test.ci`'s placeholder `overridden-by-ci` — plaintext, committed, never connected to. Same env-file mechanism every repo test entry point already uses.
