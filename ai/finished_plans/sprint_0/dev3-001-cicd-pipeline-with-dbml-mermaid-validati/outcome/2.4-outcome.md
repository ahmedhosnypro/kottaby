## 2. DEFINED BEHAVIOR Decisions (all asserted in tests)

1. **CLI modes** (plan-literal + Phase-0 §7 required contract):
   - *Explicit*: one-or-more paths as argv; each resolves cwd-first, falling back to repo root so CI wrappers may pass `git diff`-style relative paths from any cwd.
   - *Default discovery* (zero argv): array-argument `Bun.spawn(["git","ls-files","--","docs"])` — NO shell string interpolation (Tier-4 source assertions) — then tracked `.mmd` files plus tracked markdown under docs containing a raw ```` ```mermaid ```` fence substring. Deterministic UTF-16 sort. Enumeration failure ⇒ loud exit 1 (a broken checkout can never masquerade as an all-green empty set). Zero discovered files ⇒ PASS with explicit no-op message, exit 0 (empty-set semantics owned by the Task 2.3 wrapper).
   - Exit codes: **0** all green/no-op, **1** any failure/unreadable input/enumeration failure, **2** usage error (dash-prefixed flag; no flags exist by contract). Empty-string/missing files are validation failures, not usage errors.
2. **Fence extraction (markdown)**: opener = line matching `{0..3 spaces}` + ``` ```mermaid ``` word-boundary + OPTIONAL whitespace-separated info-string suffix; closer = next bare three-backtick line. Strictness choice DOCUMENTED and tested: a semicolon-glued hostile suffix (``` ```mermaid; rm -rf ~ ```) does NOT open a block at all; a whitespace-separated hostile-looking suffix DOES open but is stored as inert characters only (never executed, never expanded into any process/shell/context call) — both asserted incl. a real-process run.
   Unterminated fence ⇒ issue attributed to the OPENING line number (endLine = null in the extracted model).
3. **Keyword declaration rule**: first significant line's first whitespace-delimited token compared CASE-INSENSITIVELY via whole-token equality against curated lowercase list (`flowchart`, `graph`, sequence/class/state(-v2)/er diagrams, journey, gantt, pie, mindmap, timeline, quadrantChart, gitGraph, C4Context/Container/Component/Dynamic, requirementDiagram, sankey-beta, xychart-beta, architecture-beta, block-beta, kanban, radar where `-beta` is optional-tolerant → both forms listed explicitly rather than fuzzy-suffixed). Leading blank lines AND `%%` comment lines are skipped while locating the declaring line — REQUIRED because the three committed `.mmd` assets begin with `%%` header comments (Mermaid ignores those comments; a comments-only body still fails the emptiness rule).
4. **Line-level sanity is deliberately minimal (UNDER-flagging)**: applies ONLY to flowchart/graph family and ONLY to lines beginning with an arrow operator (`-->`, `==>`, `-.\u200b->`, `---`) with no source node token before them. Verified against the actual committed diagram corpus BEFORE implementation (zero hits ⇒ zero false positives possible); broader syntax checking stays with real Mermaid tooling by design.
5. **`.mmd` whole-file mode** validates the entire file through the same `validateDiagramSource`; markdown emits absolute `file:line` attribution computed as opening-fence line + in-block relative line. Markdown with ZERO fences in EXPLICIT mode passes with an honest "0 mermaid diagram(s)" line (prose-only docs are valid); unsupported extensions fail loudly by name.
6. **Output discipline**: per-file `✅ <path> — N mermaid diagram(s)` summary lines to stdout via `process.stdout.write`; failure details `<path>:<line>: <reason>` on stderr; final aggregate count line either way. Zero `console.*`. REQ-002 English-only operator-string exemption recorded here for this script (same write-once exemption family as outcomes 2.1 §7 / 2.2 §6).
