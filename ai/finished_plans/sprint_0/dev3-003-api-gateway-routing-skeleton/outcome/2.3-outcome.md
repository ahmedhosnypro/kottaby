## Semantic Review notes (D9 trade-offs on record)

1. **Lexical-scan caveat accepted:** scans are deliberately TEXT-level (regex over file content). They can flag occurrences inside comments or string literals — visible false POSITIVES at worst; an obfuscation-induced false negative would fail human review anyway. No AST dependency was introduced (zero-new-deps rule).
2. **A3 scope excludes `*.test.ts`:** this suite itself lives under `backend/lib/gateway/` and necessarily contains pattern literals (`"console."`, `"await import("`) to make scanners non-vacuous. Production-source scoping keeps the assertion meaningful without self-flagging; any future console usage INSIDE gateway tests remains covered by biome/oxlint rules repo-wide.
3. **A4 skips `app/api/test/` directories** defensively (test scaffolding never ships routes) while asserting the known `/api/graphql` row exists so the check can never pass "vacuously empty".
4. **Docblock `*/` hazard:** writing glob patterns like `<dir>/**/*.ts` inside JSDoc TERMINATES the block comment at the embedded `*/` (tsgo TS1127 "Invalid character" — reproduced once here and once in 2.2's route-inventory.ts; both fixed by rewording globs in prose). Carry-forward for all Phase-3+ authors.
5. Regex escaping verified against crafted fixtures — e.g. A2 uses word-boundary + optional whitespace so `revalues:[` never matches; `"\b"` on `export\s+(const|…)` prevents `exports.foo` style false hits.
