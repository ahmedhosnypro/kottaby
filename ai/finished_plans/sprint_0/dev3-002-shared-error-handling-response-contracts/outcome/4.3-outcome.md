## 1. Wiring description (direct-call seam, NOT the listener)

Task offered two consumption paths; **direct `mapGraphQLErrorByCode` call in the submit error path** matches existing code structure: RegisterForm's catch block already branched on codes synchronously, while the single-slot `registerGraphQLErrorActionListener` seam is app-scope-owned (toasts/host surfaces) — a page registering over it would steal global surfaces and fight 4.1's documented single-slot semantics.

New pure module (`mutationFieldErrors.ts`, React-free / Apollo-runtime-free):

| Export | Purpose |
|---|---|
| `ProjectedFieldError` | `{ field, message }` pair (`extensions.fields[]` projection) |
| `projectMutationFieldErrors(error)` | walks Apollo cause chain (`CombinedGraphQLErrors.errors[]`, bare extension items, `.cause` hops), re-runs each coded item through the 4.1 table with `{ contextKind:"mutation", hasForm:true }`, returns first-wins `{field,message}[]`; rows without field pairs contribute nothing |
| `FieldErrorSink<TField>` | contextual `(field, {message}) => void` matching RHF `setError(name, error)` |
| `applyProjectedFieldErrors(projected, isAcceptedField, sink)` | feeds guard-narrowed pairs into the typed sink in wire order; returns applied count |

RegisterForm submit flow (per REQ-061 ordering):
1. On mutation failure → `projectMutationFieldErrors(err)`.
2. `applyProjectedFieldErrors(projected, isRegisterFieldPath, setError(...))` where `isRegisterFieldPath` is a **type-predicate whitelist over the eight known form paths** (mirrors `AuthLabels` keys-in-use). Unknown/spoofed wire paths are DROPPED, never force-cast in — zero `as` assertions anywhere (oxlint `no-unsafe-type-assertion`).
3. `applied > 0` ⇒ early return — per-field mapping REPLACES the global alert exactly per tasks.md 4.3.BF bullet ("no global-form fallback replaced field mapping when extensions.fields[] was present").
4. `applied === 0` ⇒ pre-existing branch renders unchanged: CONFLICT → `t.emailAlreadyExists`; VALIDATION-without-fields → server-localized wire message else `t.registrationFailed`; else → `t.registrationFailed`.

**Ground-truth disclosure:** today's backend `RegistrationService.validateInput` throws `ValidationError(t.*)` WITHOUT a fields[] payload (fields absent ⇒ extensions absent). The wire path is therefore future-proofing for the REQ-015 contract and degrades to case 4 today — verified end-to-end by suite tests 6–8 (CONFLICT/VALIDATION-no-fields/malformed entries all project `[]`). No backend change was made or implied.
