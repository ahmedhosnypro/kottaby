## Design decisions of record

1. **Overload set (backwards-compatible by construction).**
   ```ts
   constructor(message: string);                                                        // legacy #1 unchanged
   constructor(code: string, message: string, options?: GraphQLErrorOptions);           // legacy #2 unchanged
   constructor(message: string, fields: readonly ApiFieldErrorType[]);                  // NEW
   constructor(code: string, message: string, options: GraphQLErrorOptions | undefined,
               fields: readonly ApiFieldErrorType[] | undefined);                        // NEW
   ```
   Disambiguation is arity/type-based (`string,string…` vs `string,array`). Legacy throw sites compile WITHOUT EDITS — proven not only by greps but by the compile itself (`tsgo -b` covers registration.service.ts etc.) plus an in-suite fixture replaying verbatim legacy call shapes asserting identical codes (`legacyShapes` test).
2. **Assertion-free branching.** Native `typeof second === "string"` + locally-declared predicate
   `isFieldsPayload(v): v is readonly ApiFieldErrorType[]` (wraps `Array.isArray`).
   Rationale on record: TS's built-in `Array.isArray` guard (`arg is any[]`) does NOT eliminate `readonly T[]` union members (TS2322 twice observed); a locally-declared predicate performs sound negative narrowing while keeping the file oxlint `no-unsafe-type-assertion` clean — ZERO casts introduced in production code or tests.
3. **Presence semantics (consumed by 2.2/2.4):** `fields === undefined` ⇒ instance prop absent AND `'fields' in extensions === false` (transport omission); explicit EMPTY array ⇒ present-but-empty on BOTH surfaces (discrimination requirement REQ-015; executably pinned).
4. **Extensions mirroring:** payload stored once (`this.fields`) and mirrored BY REFERENCE into `extensions.fields` so GraphQL transports carry it automatically with no per-boundary re-wiring; caller-supplied extension keys survive; ctor param wins over same-key caller extensions.
5. **23505/SQLite path verified — NO code change needed** ("adjust minimally if needed" clause resolved as *not needed*): `translateDbError` already yields ConflictError whose `code` AND `extensions.code` are both `"CONFLICT"` (envelope-compatible classification) with producer-localized message, original preserved on `.cause`, idempotent short-circuit for prior DomainErrors, identity passthrough otherwise. The earlier-shipped taxonomy composes: `normalizeErrorCode("CONFLICT") → "CONFLICT"` → HTTP 409.
6. **NotFoundError entity semantics (REQ-052) preserved untouched:** correct convention pinned (`("USER") → USER_NOT_FOUND`); current double-suffix behavior on full-code misuse documented and regression-LOCKED in tests (any drift = loud failure) rather than silently "fixed" — behavior changes belong to an explicitly-scoped future decision.
