## 3. Code fix applied during verification (root-caused via probe)

**Bug:** POST handler re-buffering used `new NextRequest(...)` while the import was type-only — `import { type NextRequest, NextResponse } from "next/server"` — producing a runtime `ReferenceError: NextRequest is not defined` for EVERY well-formed JSON POST (the old code path never used NextRequest as a value; this use is new to 3.1's transport re-buffer). tsgo did not flag it; Turbopack strips type-only imports, so it only detonated at runtime.

**Fix:** value import `{ NextRequest, NextResponse }` (`app/api/graphql/route.ts:5`). Diagnostics confirm: with fix, live HTTP `{"query":"{ _health }"}` → `{"data":{"_health":"ok"}}` HTTP 200; biome/oxlint/tsgo accept the value import (it IS used as a value). A temporary `[PROBE-DIAG]` stderr line added during root-cause capture was fully reverted.
